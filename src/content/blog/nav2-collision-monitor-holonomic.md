2026년 2월 12일, Nav2 Collision Monitor의 홀로노믹 속도 판정을 고치는 [navigation2 PR #5954](https://github.com/ros-navigation/navigation2/pull/5954)를 올렸습니다. 옆으로 움직이는 로봇이 정지 상태용 폴리곤에 머물던 문제입니다. 같은 날 [문서 PR #871](https://github.com/ros-navigation/docs.nav2.org/pull/871)도 열었습니다.

## 무엇이 문제였나

`velocity_polygon`은 속도 명령에 맞춰 충돌 검사에 쓸 폴리곤을 고릅니다. 서브 폴리곤마다 선속도와 각속도 범위를 지정하고, 홀로노믹 설정에서는 이동 방향 범위도 지정합니다. 여러 조건에 맞으면 목록의 첫 번째 폴리곤을 씁니다.

문제는 선속도 범위를 x 성분에만 비교한다는 점이었습니다. 예를 들어 이동용 폴리곤의 `linear_min`이 0.1 m/s인데, 명령이 $v_x = 0$, $v_y = 0.5$ m/s이면 실제로는 움직이고 있어도 선속도 조건에서 탈락합니다. 정지용 설정만 0을 포함한다면 측면 주행 중에도 정지용 폴리곤을 고릅니다.

옴니나 더블 스티어링 AMR은 차체 방향을 바꾸지 않고 측면으로 이동할 수 있습니다. 이런 로봇에서는 앞뒤 주행뿐 아니라 측면과 대각선 속도에도 맞춰 검사 영역을 나눠야 합니다. x 성분만으로는 느린 측면 이동과 빠른 측면 이동을 구분할 수 없습니다.

이 문제와 합성 속도를 쓰자는 방향은 다른 사용자가 올린 [이슈 #5740](https://github.com/ros-navigation/navigation2/issues/5740)에 먼저 있었습니다. 저도 옴니 로봇을 개발하며 필요한 기능이라 2월 3일 시험을 돕겠다는 댓글을 남겼고, 이후 수정 PR을 올렸습니다.

## 원인과 수정

기존 `isInRange()`는 x 속도와 각속도로 `in_range`를 먼저 만들었습니다. 홀로노믹이면 뒤에서 방향 조건을 `&=`로 더했지만, x 속도 검사에서 이미 false가 된 값은 방향이 맞아도 바뀌지 않습니다.

각속도는 공통으로 검사하고, 선속도는 로봇 종류에 따라 나눴습니다. 홀로노믹 분기에는 다음 검사를 넣었습니다. 아래는 PR diff에서 주석을 뺀 발췌입니다.

```cpp
const double magnitude = std::hypot(cmd_vel_in.x, cmd_vel_in.y);
const double direction = (magnitude > 0.0) ? std::atan2(cmd_vel_in.y, cmd_vel_in.x) : 0.0;
in_range &= (magnitude <= sub_polygon.linear_max_ &&
  magnitude >= sub_polygon.linear_min_);
```

홀로노믹에서는 $\sqrt{v_x^2 + v_y^2}$를 선속도 범위와 비교하고 방향은 `atan2`로 구합니다. 정지 시 방향은 0으로 둡니다. 비홀로노믹은 기존처럼 부호 있는 x 속도를 쓰므로, 음수 범위로 후진을 정의한 설정을 유지합니다.

홀로노믹 설정의 `linear_min`, `linear_max`는 이제 0 이상의 속력 범위입니다. 후진도 음수 속도가 아니라 방향 범위로 나타냅니다. 이에 맞춰 기존 단위 테스트의 후진과 좌우 선속도 범위를 수정했습니다. 문서 PR에서는 두 로봇 종류의 파라미터 의미를 구분하고, 8방향과 정지 상태의 설정 예시를 추가했습니다.

## 리뷰와 머지

리뷰에서 main에 맞지 않는 유틸리티 함수 변경을 되돌리고, 린트와 DCO 서명, 테스트 파일의 저작권 헤더를 정리했습니다. 메인테이너는 CI 수정분을 받도록 rebase를 요청하면서 패치 전후의 동작도 보여 달라고 했습니다.

그래서 `collision_monitor` 노드와 정적 스캔 점을 두고 측면 속도 명령을 직접 발행하는 최소 재현 영상을 올렸습니다. 패치 전에는 폴리곤이 바뀌지 않고, 패치 후에는 이동용 폴리곤으로 바뀌는 비교입니다. PR 본문에는 자체 홀로노믹 하드웨어의 측면과 대각 이동 확인도 기록했습니다. 이 글에서 새 실차 시험을 한 것은 아닙니다.

Steve Macenski는 코드 PR을 승인했고, 문서 수정 후 두 PR을 2026년 2월 17일 UTC에 머지했습니다. 한국 시각으로는 2월 18일입니다. 코드 머지 커밋은 `181570e`입니다.

## 지금 상태

코드 PR #5954와 문서 PR #871은 모두 머지되었습니다. 코드 수정은 main 계열 1.5.x 릴리스에 포함되고, Jazzy에는 백포트되어 1.3.12부터 들어 있습니다. 1.3.11 소스에는 없고 1.3.12에는 합성 속도 검사가 있는 것을 확인했습니다.

다만 머지된 문서 예시까지 모두 검증을 마쳤다고 볼 수는 없습니다. 이번에 예시의 방향 범위와 첫 일치 선택 규칙을 다시 대조하니, 앞선 항목과 범위가 겹쳐 `forward_right`와 `backward_right`가 선택되지 않는 문제가 남아 있었습니다. 코드 수정과는 별개이며, 이 문서 예시를 고치는 후속 PR은 아직 올리지 않았습니다.
