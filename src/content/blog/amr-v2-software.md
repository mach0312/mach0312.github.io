피트인에서 2세대 배터리 이송 로봇(AMR)의 소프트웨어를 만들고 있습니다. 글 날짜는 시스템, 내비게이션, 로봇 모델 저장소를 만든 날이고, 내용은 2026년 11월 기준입니다. 비공개 작업이라 코드 대신 구조와 제 역할, 남은 일을 적습니다.

## 무엇을 만들고 있나

전기차 배터리 교체 스테이션에서 교환용 배터리 팩을 옮길 이동로봇입니다. 앞뒤 바퀴가 각각 조향과 구동을 해서 제자리 회전과 옆걸음이 되고, 차체에는 리프트, 포크, 다축 상판이 있습니다. 관제 경로를 따라 달리는 것뿐 아니라 작업 장치를 움직이고, 이상이 생기면 멈추고 원인을 알리는 소프트웨어가 필요합니다.

## 1세대와 달라진 점

1세대 배터리 이송 AGV의 파이썬 제어 프로그램은 조이스틱, 모터, PLC, 센서, 관제 통신을 묶고 자석 라인을 따라 주행합니다. 2세대도 이 코드를 가져와 시작했고, 이후 상태 저장소와 명령 처리기를 중심으로 구조를 나눴습니다.

| | 1세대 | 2세대 |
|---|---|---|
| 기반 | ROS 2 Humble | Ubuntu 24.04, ROS 2 Jazzy |
| 위치 파악 | 자석 라인과 자기 마커 | 듀얼 라이다, RTAB-Map, 정밀 구간은 PGV |
| 주행 | 라인 트레이싱 | Nav2 경로 그래프 주행 |
| 구동 | 모터 드라이버 직접 제어 | ros2_control, CANopen |
| 관제 연동 | rosbridge 위 자체 토픽 | 자체 토픽에 VDA5050 v3(MQTT) 추가 |

## 시스템 구성

시스템 제어는 명령을 검사하고 PLC, 리프트, 상판을 다룹니다. 내비게이션은 위치 추정과 Nav2 경로 추종, 주행 명령 관리를 맡습니다. VDA5050 커넥터는 MQTT 관제 주문을 로봇 명령으로 바꾸고 로봇 상태를 보고합니다. 공통 메시지는 어느 한쪽에 종속되지 않는 인터페이스 패키지로 둡니다.

설계에서 중요하게 본 것은 다음과 같습니다.

- **관제 명령은 같은 검사를 받습니다.** VDA5050 명령도 기존 명령 처리기의 인터록을 통과합니다. 프로세스 경계마다 상대의 생존을 보고, 내비게이션이 명령에 답하지 않으면 실패로 처리합니다.
- **정상은 증명해야 통과합니다.** 건강 값은 비정상을 기본으로 두고, 스레드 생존은 마지막 갱신 시각으로 판단합니다. 멈춘 스레드는 자기 죽음을 보고할 수 없기 때문입니다.
- **고장은 계통별로 검사합니다.** 명령마다 필요한 계통을 검사하고, 비상정지와 작업 초기화는 건강 검사 앞에서 처리합니다. 고장 때문에 복구 수단까지 막히지 않게 하기 위해서입니다.
- **물리 비상정지는 PLC 안전 회로가 집행합니다.** ROS 노드만으로 차단을 책임지지 않습니다.
- **관제가 경로를 정하고 로봇은 실행합니다.** 허용 구간 밖의 엣지를 닫아 Nav2 route server의 탐색 범위를 제한합니다. 코너 감속, 노드 위 정지, 제자리 회전은 경로 추종 제어기에서 처리하도록 구성했습니다.

## 내가 맡은 부분

시스템, 내비게이션, 모델 저장소를 만들었고, 2026년 4월에는 상위 저장소에 아키텍처, 설계 결정, 결함과 남은 일, 인터페이스 계약을 모으기 시작했습니다. 개인 역할은 초기 커밋과 현재 코드의 이력이 확인되는 범위로 한정합니다.

- **시스템 제어**: 상태 저장소와 명령 처리기 구조, 계통별 인터록, PLC 안전 래치, 범퍼 방향을 구분하는 비상정지 출처 진단, 현재 오류 목록 발행, 제어 프로그램과 별도로 도는 감시 노드
- **센서와 배터리**: 라이다 시각 동기 서비스 구성, 두 IMU의 차체 중심 합성 노드, BMS 수신 노드
- **구동**: 기존 ros2_controllers 제어기 기반에 이중 조향 기구학과 오도메트리, 조향 변화 제한과 속도 조정을 넣은 ros2_control 플러그인
- **내비게이션**: Nav2 설정과 기동 구성, 주행 명령 관리 노드, 전방향 경로 추종 플러그인, 경로 실행 설계 기록. 공개 예제에서 출발한 기동 파일과 초기 Nav2 클라이언트 자체를 제 원작으로 세지는 않습니다. 관리 노드는 이후 비동기 클라이언트로 바꿨습니다.
- **연동과 도구**: VDA5050 주문 실행과 상태 보고, 헤딩 기준 조이스틱 조작과 가속도 제한 노드, PGV 정렬 제어, Vue와 three.js 기반 상태 표시·조작 웹, 사내 개발자 매뉴얼

PGV는 Data Matrix 코드의 상대 위치를 읽어 정렬에 사용합니다. 같은 제어 패키지의 다른 판이 [omni-docking-bench](/blog/omni-docking-bench/) 실험의 제안 방법입니다.

또한 옆걸음 중 x 방향 속도만 보고 정지 상태용 감시 영역을 고르던 Nav2 collision monitor 문제를 수정했습니다. 전방향 이동은 속도 크기로 판정하도록 바꿨고, 2026년 2월 upstream에 머지됐습니다([PR #5954](https://github.com/ros-navigation/navigation2/pull/5954)).

CANopen 설정, 상판 모터 노드, 리프트 드라이버, 하드웨어 모델 일부는 동료와 함께 만들었습니다. 동료는 다축 단일 버스 구조와 폴트 자동 회복을, 저는 원점 잡기 소유권, 조그, 포크 축, 재부팅 감지, 외부 명령 공존을 더했습니다. PLC 명령 연동, 리프트 연결, 상판 제어의 초기 작업과 정렬 제어기 초기 시험에도 동료의 기여가 있습니다. Nav2, RTAB-Map, ros2_control, ros2_canopen, 조이스틱 드라이버 등 공개 패키지를 가져온 것은 개인 개발 실적으로 세지 않았습니다.

## 지금 상태

무인 운용 승인은 현장 검증을 마칠 때까지 보류된 상태이고, 소프트웨어는 지금도 개발 중입니다. 주행 실패 시 정지 확인, 비상정지 해제 뒤 상판의 자동 재개 방지 등 우선 차단 항목은 코드 수정과 자동 검증을 마쳤지만, 실차 승인을 뜻하지 않습니다. 개발용 설정을 정식 운용 조건으로 되돌리는 일도 남아 있습니다.

확인하지 못한 것은 다음과 같습니다.

- 실차 경로 주행, 일시 정지와 재출발, 취소, 충돌 정지
- 관제 경로 강제와 코너 감속·정지·회전 (코너 처리는 단위 시험만 통과)
- 부하를 건 리프트와 상판 동작, 실제 관제와의 VDA5050 연동
- 지도 정합 정확도 지표, 라이다 시각 동기 오차, IMU 합성 정확도
- 개발자 매뉴얼 예제의 실장치 동작 (가짜 노드나 문법 검사로만 확인)

지도 정합을 검증하기 전까지 VDA5050 위치 확정 값은 비워 둡니다. 주문의 노드·엣지 액션 실행 계층은 미구현이고, BMS 수신 값도 로봇 상태와 VDA5050 보고에 아직 연결하지 않았습니다. 경로와 스테이션 좌표의 기준 정보를 관제로 옮기는 일도 남았습니다. 베이스와 포크의 협조 정렬은 실기 전 초안이며, 중복 실행 방지와 배포 되돌리기 등 안전 감사 후속 작업도 끝나지 않았습니다.
