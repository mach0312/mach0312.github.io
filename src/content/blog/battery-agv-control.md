피트인의 전기차 배터리 교체 스테이션에서 배터리를 운반하는 1세대 AGV 제어 프로그램에 참여했습니다. 프로젝트는 동료가 2023년 9월 PyBullet 시뮬레이션으로 시작했고, 저는 2024년 1월에 합류했습니다. 글 날짜는 저장소를 만든 날이며, 아래 내용은 2026년 11월 기준으로 정리했습니다.

## 무엇을 하는 프로그램인가

주행 모터, 배터리를 올리고 내리는 리프트, 상판의 서보, 자기 센서와 관제 통신을 묶는 Python 프로그램입니다. ROS 2로 관제의 명령을 받고, 로봇의 위치와 작업 상태를 다시 보냅니다. 현장 주행은 자기 센서로 선로와 마커를 읽는 라인 트레이싱을 중심으로 구성되어 있습니다.

배터리를 옮기는 작업은 주행만으로 끝나지 않습니다. 목적지 이동과 리프트 동작, 상판의 상태가 함께 맞아야 합니다. 관제에서 명령을 보냈다는 사실과 로봇이 실제로 수행 중인지, 완료했는지도 구분해야 합니다. 이 프로그램은 장치 통신과 작업 상태 처리를 함께 맡습니다.

## 내가 맡은 부분

프로그램의 기반과 현재 코드 대부분은 동료가 작성했습니다. 제가 전체 제어기를 설계하거나 모든 장치 드라이버를 만든 것은 아닙니다. 그 위에서 수동 조작과 관제 연동에 필요한 부분을 추가하고 수정했습니다.

조이스틱 쪽에서는 Linux 입력 장치를 읽는 evdev 기반 입력 처리, 버튼과 축 값의 매핑, 장치 탐색과 연결 확인 코드를 작성했습니다. 입력을 읽는 부분은 제 코드가 남아 있지만, 현재의 연결 끊김 처리와 스레드 보호에는 동료의 후속 변경도 포함되어 있습니다.

ROS 2 연동에서는 호기별 이름 공간과 명령·응답·상태 토픽을 정리하고, 상판 관절 상태를 발행하는 부분을 추가했습니다. rosbridge 접속자 목록에서 관제 서버의 연결 여부를 구분하는 처리도 맡았습니다. 현재 서버 감시 전체는 이후 동료들이 보완한 코드와 함께 동작합니다. 관제에서 보내는 일시정지 요청을 받아 주행의 정지 상태에 반영하는 처리도 추가했습니다. 일시정지는 진행 중인 작업을 남겨 두는 요청이고, 작업 취소는 그 작업을 정리하는 요청이므로 같은 명령으로 취급하지 않았습니다.

운영 로그는 실행할 때마다 파일이 갈라지던 방식에서 날짜를 기준으로 모으도록 바꾸고, 프로그램이 다시 시작된 지점을 기록했습니다. 로그 유틸 분리에도 참여했습니다. 다만 현재의 비차단 기록과 로그 공유 처리까지 모두 제 작업으로 묶지는 않습니다.

## 구조와 동작

메인 제어 프로그램은 조이스틱 입력, 장치 통신, 상판 제어, ROS 2 인터페이스를 스레드로 나누어 실행합니다. 수동 조작과 관제 명령은 같은 로봇 상태를 참조하고, 통신 모듈이 모터와 PLC에 명령을 전달합니다. 관제에는 현재 위치, 목표 위치, 적재 여부와 작업 진행 상태를 발행합니다.

같은 저장소에는 제가 작성한 별도의 PyBullet 시뮬레이터도 있습니다. 가상 AGV의 위치와 작업 상태를 두고, rosbridge를 통해 명령과 응답을 주고받는 구조로 구성했습니다. 이 시뮬레이터와 현장에서 실행하는 제어 프로그램은 구분해야 합니다. 시뮬레이션 코드가 있다는 사실만으로 실차 동작을 검증했다고 볼 수는 없습니다.

## 작업 취소에서 확인한 경계

이후에는 관제에서 진행 중인 작업만 취소하는 명령을 추가했습니다. 기존에는 비상정지를 걸고 해제하면서 작업을 초기화하는 경로를 사용했습니다. 작업 취소와 비상정지 상태 변경을 분리하기 위해, 비상정지 플래그를 건드리지 않고 작업을 정리하는 경로를 만들었습니다.

취소 응답만 보내는 것으로는 부족했습니다. 대기 명령이 남거나 취소 직후 받은 다음 명령이 지워지는 경우, 정렬 세션이 남아 후속 동작을 다시 예약하는 경우를 함께 다뤘습니다. 리프트 제어의 잔존 목표와 일회성 상태도 정리하도록 수정했습니다. 이 부분은 ROS와 장치를 대체한 오프라인 테스트로 확인했습니다. 테스트가 통과했다는 것과 실물 드라이브가 의도대로 정지한다는 것은 별개의 확인입니다.

## 지금 상태

이 제어 프로그램은 안양 스테이션의 AGV 1~3호기에서 운용 중입니다. 다만 프로그램 전체의 현장 운용 확인이 제가 추가한 모든 변경의 실차 검증을 뜻하지는 않습니다.

작업 즉시 취소와 취소 뒤 상태 정리는 기본 브랜치에 반영되었고, 관련 오프라인 테스트도 통과했습니다. 리프트 이동 중 취소했을 때의 실제 드라이브 정지, 주행 중 정지 거동, 핀 체결이나 원점 탐색 중 취소, 연동 설비로 비상정지가 전파되지 않는지는 이번 확인으로 검증하지 못했습니다. 스레드 사이의 상태 접근에 경합 가능성이 남아 있다는 점도 해결 완료로 쓰지 않습니다.
